CLAUDE.md 규칙 10-b의 인계 수단은 대상에 따라 갈린다.
- **`` `[다른 PC]` `` (다른 PC의 세션)**: 프롬프트를 `[프롬프트]` 라벨 + 코드블록으로 답에 보여주기만 한다. 복사는 사용자가 직접 `Ctrl+C`로 한다.
- **`` `[🆕 새 세션]` `` (동일 PC, 새 터미널/클리어)**: 2026-08-18부터 프롬프트 코드블록이 아니라 `~/.claude/skills/handoff/SKILL.md` 규약대로 `<프로젝트>/.claude/handoff/pending/{YYYYMMDD-HHmm}-{slug}.md` 파일을 써 둔다. 다음 세션에서는 `/handoff` 한 마디만 치면 스킬이 가장 오래된 대기 항목을 읽어 이어서 진행하고, 끝나면 `done/`으로 옮긴다.

**왜 나눴나(2026-08-18 사용자 지적)**: "새 세션"은 실무상 거의 항상 동일 PC에서의 `/clear`·새 터미널이었고, 다른 PC로의 이동은 사용자가 직접 push까지 하고 있어 핸드오프가 필요 없었다. 진짜 불편은 "매번 프롬프트 전문을 복사-붙여넣기 해야 하고, 여러 개 쌓이면 순서를 직접 기억해야 한다"는 것 — 동일 PC라 `cwd`가 그대로 유지되므로 파일을 프로젝트 로컬(`.claude/handoff/`, `.gitignore` 대상)에 두고 스킬 이름 하나(고정 문구)로 부르는 쪽이 실제 문제를 없앤다. 스킬(로직)은 전역, 데이터(md)는 프로젝트 로컬로 분리 — 여러 프로젝트가 전역 폴더 하나에 뒤섞이는 걸 피함.

**히스토리**: 2026-08-07에 `~/.claude/session-handoff.ps1`로 클립보드 자동 복사(+한때 새 탭 자동 오픈까지)를 시도했으나, 같은 날 실사용해보니 그닥 쓸모가 없어 사용자가 직접 원복 요청. 스크립트 삭제, CLAUDE.md·README.md 모두 코드블록 제시 방식으로 되돌림. 새 탭 자동 오픈은 그보다 먼저 `wt.exe`가 엉뚱한 창을 여는 문제로 이미 제거된 바 있었다.

**교훈**: 이 종류의 "편의 자동화"는 실측 없이 도입하면 되돌리는 비용(코드+문서+메모리 3곳 동기화)이 든다 — 다음에 비슷한 제안이 나오면 먼저 시험적으로 며칠 써보게 하고 굳히는 편이 나을 수 있다. `handoff` 스킬도 같은 리스크가 있으니 며칠 실사용 후 문제가 보이면 되돌릴 수 있다는 전제로 도입했다.
