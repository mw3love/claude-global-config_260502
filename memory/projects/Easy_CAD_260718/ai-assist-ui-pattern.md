Easy CAD에서 "텍스트/프롬프트 → AI → 결과물"을 기존 입력창에 얹을 때는 이렇게 한다
(2026-08-11~12 Mermaid 가져오기 + AI 이미지→도면 통합 deep-interview에서 확정):

1. **분리형 입력** — AI 프롬프트 칸과 최종 결과 칸(사람이 직접 쓸 수도 있는 칸)을 같은
   박스로 겸용하지 않는다. AI 버튼은 결과 칸을 "채워줄 뿐"이고, 그 칸은 항상 직접
   편집·붙여넣기 가능해야 한다. 통합 단일박스(AI가 자기 내용을 자기가 갈아치우는 구조)는
   사용자가 이미 손으로 고치던 내용을 실수로 덮어쓸 위험 때문에 기각됨.
2. **"수동 모드" UI를 따로 만들지 않는다** — 게이트웨이를 안 쓰고 싶으면 그냥 결과 칸에
   직접 타이핑/붙여넣기 하면 된다. 옛 "AI 이미지→도면"은 체크박스+프롬프트복사 버튼으로
   된 전용 "수동 모드"가 있었는데, 텍스트 기반으로 바뀌면서 이게 통째로 불필요해짐 —
   결과 포맷 자체가 사람도 직접 쓸 수 있는 텍스트(Mermaid)라면 별도 모드 UI가 군더더기.
3. **모델 드롭다운은 전체 나열 대신 추천 1~2개로 압축** — 계열(예: gpt/gemini)별 가성비
   최선 1곳씩만 "(추천1)"/"(추천2)"로 표시. [[ui-simplicity-principle]]과 같은 축.

**Why:** 사용자 최상위 기준이 "심플·직관적"([[ui-simplicity-principle]] 참조)이고, AI
보조 기능이 늘 때마다 매번 전용 UI를 새로 만들면 그 원칙과 정면충돌한다. 이번 세션에서
"이미지→AI→JSON" 파이프라인 전체(수동모드 포함)를 폐기하고 "텍스트→AI→Mermaid"로
합치면서 위 세 원칙이 자연스럽게 드러났다.

**How to apply:** 다음에 다른 AI 보조 생성 기능(예: 표·심볼 자동배치 등)을 붙일 때도
이 세 가지를 먼저 검토한다 — 특히 "이 결과 포맷을 사람이 직접 쓸 수 있는가?"가 참이면
수동 모드 UI를 따로 만들 필요가 없다는 신호.
