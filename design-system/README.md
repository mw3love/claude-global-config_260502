# Design System — 디자인 취향 축적 문서

`design-bakeoff` 스킬이 매 라운드 시작 전에 읽고, 라운드가 끝나면 갱신하는 저장소.
목적: 사용자는 디자이너가 아니라서 매번 "이건 되고 이건 안 되고"만 판정하는데, 그 판정이
휘발되지 않고 쌓여서 다음 라운드에 같은 시행착오를 반복하지 않게 하는 것.

## 구조

```
design-system/
├── README.md          이 파일
├── preferences.md      범용 취향 — "확인됨"(2개 이상 프로젝트)과 "가설"(1개) 두 층
└── projects/
    └── <slug>.md        프로젝트별 확정 토큰 + 라운드별 채택/탈락 로그
```

## 쓰는 법

- **읽기(라운드 시작 전)**: `preferences.md` + `projects/<이번 프로젝트>.md`를 먼저 훑는다.
  이미 탈락한 스타일은 새 비교 후보에서 자동으로 뺀다.
- **쓰기(라운드 끝날 때)**: `projects/<slug>.md`에 이번 라운드 확정 내용 + 탈락 후보와 이유를
  바로 추가한다(미루면 "왜 탈락시켰는지"가 휘발됨).
- **재검토(이미 확정된 항목을 다시 여는 라운드)**: 새 결정만 적지 말고 **이전 확정값 →
  새 결정, 왜 바뀌었는지**를 반드시 같이 남긴다. 같은 요소가 **3번째로 뒤집히면**
  `design-bakeoff` 스킬이 재조정 전에 "요소가 아니라 스코프 자체가 틀렸을 가능성"을
  사용자에게 먼저 물어야 한다(스킬 쪽 "뼈대 재검토" 절 참고) — 이 파일은 그 판단의 근거가
  되는 이전 확정 기록을 보존하는 역할.
- **승격**: 같은 취향이 **서로 다른 프로젝트 2개 이상**에서 반복 확인되면 `preferences.md`로
  옮긴다(1개 프로젝트 경험만으로 범용 취향이라 단정하지 않는다 — 아직은 가설).
