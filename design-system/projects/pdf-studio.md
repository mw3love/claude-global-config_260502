  좌측 바, 삽입 캐럿. 배경·패널 같은 상시 노출 요소엔 안 씀([[preferences]]의 범용 원칙 재확인).

  버튼이 메인 캔버스를 배타적으로 바꾸는 게 아니라, 레일 오른쪽에 해당 사이드패널을 여는
  방식 — A1(레일 자체)은 유지, "배타적 모드 전환" 동작 방식은 폐기. 최상단에 전통
  메뉴바(파일·편집·보기·주석·페이지·도구·도움말) + 자주 쓰는 툴바 버튼도 라운드3에서
  추가(M0의 "메뉴바 없음" 전제 폐기). **라운드4로 다시 조정된 부분**: 레일은 "읽기"
  버튼 없이 **주석목록·구성 2개뿐**(패널이 하나도 안 열린 상태가 곧 읽기). 주석 도구는
  사이드패널이 아니라 **메인 툴바**에 있고, 도구 선택은 패널 열림/닫힘과 완전히 무관함
  (사이드패널은 "주석목록"으로 성격이 바뀜 — 도구선택 UI가 아니라 정리·점프 전용).
- **페이지 구성 화면 = 좌측 세로 리스트(폭 가변, `QSplitter`) + 메인 캔버스 확대 미리보기.**
  메인영역 썸네일 그리드 방식은 폐기.
- **삽입 드롭존 = 캐럿**(얇은 선, 리스트에서는 가로 방향). `QListView` 기본 드롭 인디케이터.
- **다중선택 = 체크박스**(색/테두리 방식 아님 — 포커스 표시와 채널 분리 목적).
- **우클릭 메뉴 = 행 전체가 타겟**, 캐럿 선 자체가 타겟 아님(조준면 확대).

주석 상호작용(별도 축, 실제 동작하는 라이브 데모로 비교):

- **하이라이트 — "좋음", 그러나 데모보다 요구가 넓음.** 데모는 텍스트 드래그 하나만
  보였는데, 사용자는 **"텍스트 드래그"와 "자유 사각형(OCR 인식 기반)" 두 도구를 별도
  버튼으로** 요구함 — 자유 사각형도 그 안의 텍스트를 OCR로 인식해서 앵커링해야 함(완전
  자유형 낙서가 아니라 두 경로 다 텍스트 기반).
- **밑줄·취소선 — "좋음", 데모의 단순화를 정확히 지적.** 데모는 시연 편의상 전체 텍스트에
  토글을 걸었는데, 사용자가 "실제로는 드래그한 부분만 적용되어야" 한다고 정확히 짚음(데모
  한계로 정확히 인지, 오해 아님) — 실제 구현은 밑줄·취소선도 하이라이트와 같은 텍스트
  드래그-선택 메커니즘을 공유해야 함. 해제는 ⓐ 같은 도구 버튼 재클릭(토글) 또는 ⓑ 선택
  도구로 그 주석을 골라 삭제, 둘 다 지원.
- **메모(아이콘 숨김+클릭 시 인라인 팝업) — "싫음", 보류.** "이렇게 아이콘으로 숨기는
  메모형식은 일단 필요없음... 다만 문서 위에 작성하는 텍스트 입력이 필요함" — 즉 별도
  아이콘 마커 패턴 자체가 불필요하다는 판정이지, 인라인 편집(팝업 대신 문서에 직접
  쓰기)이라는 방향은 여전히 맞다. 실질적으로 이 요구는 기존 "텍스트 상자(freetext)"
  도구와 겹친다 — freetext가 이미 팝업(`QInputDialog`) 방식이라 같은 문제를 안고 있으므로,
  note를 별도로 개선하는 대신 **freetext를 인라인 편집으로 고치는 쪽에 이 요구를 흡수**하는
  방향으로 다음 구현 라운드에서 검토.

이번 라운드는 시안 확정까지만(design-bakeoff 스킬 7단계 원칙 — 코드 반영은 별도 단계,
승인 게이트 유지). 코드 반영 여부·순서는 사용자 확인 후 진행.

- 화살표 도구 신규(클릭=머리 고정, 드래그로 길이조정, 캡션 입력창).
- 하이라이트·밑줄·취소선 렌더링을 단어별 개별 표시 → 드래그 범위 전체를 하나로 이어서
  표시하도록 변경("사용자 피드백 2건" 반영이라고 아티팩트에 명시).

**코드 반영 범위 — 뼈대만, 신중하게 골라서.** 사용자에게 "지금 커밋한 코드를 라운드4에
맞춰 되돌릴지" 물었을 때, 전체 차이를 한번에 모으는 안이 아니라 **"도구 위치 + 패널
성격 + 읽기버튼 제거"만** 콕 집어 "지금 되돌리기"를 택함 — 화살표·자유사각형 방식·
검색창 위치·툴바 접기 등 나머지는 스코프 밖으로 명시적으로 남겨둠. **좁게 확인받은
범위만 실행하고 나머지는 안건으로만 기록해두는 것이 맞다**는 사례.

**실측 부작용 — QToolBar에 숨긴 채 추가한 위젯은 나중에 보여도 자리를 못 잡음.**
도구를 툴바로 옮기는 되돌림 작업 도중 실제로 걸린 버그. 상세 원인·해법은
`CLAUDE.md`(PDF_Studio 프로젝트) "Qt 실측 버그" 항목 참조 — 이 프로젝트 밖에서도
`QToolBar.addWidget()` + 조건부 표시(색 스트립·옵션바처럼 도구별로 보였다 숨었다
하는 위젯)를 쓸 일이 있으면 재발할 수 있는 일반적인 Qt 함정이라 여기 요약만 남긴다:
① 위젯을 숨긴 채로 `addWidget()`하지 말 것(반환된 `QAction.setVisible()`로 여닫을 것)
② 같은 줄에 다 못 담을 만큼 위젯이 많으면 Qt가 소리 없이 오버플로 팝업으로 치워
숨겨진 것처럼 보이는 동일 증상이 재발하므로 `addToolBarBreak()`로 줄을 나눌 것.

**함정 — 같은 프로젝트를 여러 계정 세션이 동시에 다루면 라운드 번호가 충돌한다.**
이 프로젝트는 다른 계정(jjrftech)에서도 병행 작업됐는데, 그 세션의 대화 기록이
이쪽 세션엔 안 보이니 "다음 라운드 번호"를 각자 독립적으로 매겨 똑같은 사건을
"라운드3"과 "라운드4"로 다르게 부르는 충돌이 실제로 발생했다(git push 직전 발견,
`git pull`로 원본을 받아 수동으로 재배치·재번호해 해소). 여러 계정·세션이 같은
프로젝트의 design-system 기록에 동시에 쓸 수 있는 구조라면, push 전에 원격이
앞서 있지 않은지 먼저 확인할 것 — 특히 라운드 번호처럼 "다음 번호"를 로컬 상태만
보고 매기는 값은 조용히 충돌한다.

스타일로 떴는데, 코랄 배경 위에서 튀어 보여(스크린샷으로 발견) `theme.py`에
`QToolButton#panelCollapseHandle` 규칙을 추가해 패널색·테두리로 맞춤 — 패널 헤더 안
❮ 버튼은 `setAutoRaise(True)`라 별도 스타일 없이도 배경에 잘 묻어 그대로 둠.

**검증 상태 — 대부분 실조건검증(오프스크린 + 실제 GUI 스크린샷).** 시작 상태(읽기,
패널폭 0)·레일 클릭 열기·헤더 ❮ 닫기·핸들 클릭 재열기(마지막 모드 복원)·핸들 재클릭
닫기·다른 모드(구성) 전환 후 같은 왕복까지 스모크 테스트로 확인. 압축 아이콘 토글도
28→18→28px 왕복 확인. `w.grab()` 스크린샷으로 패널 열림/압축모드/닫힘 세 상태 모두
눈으로 확인(닫힘 상태에서 핸들 버튼이 실제로 남아 있고 패널색과 어울리는지까지 확대
크롭으로 확인). **여전히 미확인**: 실제 마우스로 핸들 버튼(14×26px, 작은 타겟)을 누르는
제스처 자체, 압축 모드에서 실제 한글 툴팁 가독성.

### 라운드12 (2026-09-11, 같은 날 세 번째 후속) — 시인성 2차 실측 + 세부 조정

라운드11 결과를 실제 화면 스크린샷 3장으로 다시 본 사용자가 세 가지를 지적:

1. **압축 토글·핸들 둘 다 시인성 낮음** — 유니코드 글자만 놓고 아이콘 크기를 아예
   지정 안 한 게 원인. `toolbar_compact`/`toolbar_expand`(업계 표준 압축·전체화면
   아이콘)·`chevron_left`/`chevron_right` 듀오톤을 새로 만들어 다른 도구 버튼과
   같은 크기·굵기로 맞췄다. **1차 아이콘 시도 실패** — 코너 꺾쇠+화살촉 없는
   대각선만으로 두 상태 방향을 나타내려 했더니 화살촉이 없어 두 아이콘이 사실상
   똑같아 보였다(스크린샷 확대로 자체 발견) — "꺾쇠가 중앙 쪽/모서리 쪽"이라는
   위치 차이로 상태를 구분하는 표준 관례로 바꿔 해결.
2. **핸들 폭이 너무 두꺼움(20px) → 절반이 적당** — 10×48px로(높이는 유지) 축소,
   `QSplitter.setHandleWidth()`도 맞춰 줄임.
3. **압축 토글을 도구줄 버튼으로 두는 것 자체가 별로** — "메뉴에 숨기던지 우클릭으로
   숨기던지"라는 요청으로 버튼을 완전히 없애고 `보기` 메뉴 항목(`view.compact_toolbar`
   커맨드)으로 옮김. 버튼이 없어지며 그 아이콘 두 개(`toolbar_compact`/
   `toolbar_expand`)도 다시 orphan이 돼 제거 — **아이콘 하나를 두 라운드 만에
   만들었다 지운 사례**(1차 실패로 재설계 → 2차에서 버튼 자체가 없어짐).
4. (덤) 테마 선택도 "순환 버튼" 대신 "칩 3개 중 바로 클릭" 방식으로 바꿔 달라는
   요청 — 원형 칩 3개(테마 accent 색으로 채움, 활성 테마는 ink색 링)로 교체.
   `next_theme_id()`(theme.py)·`_cycle_theme()`도 이제 안 쓰여 같이 제거.

**패턴 메모** — 이 프로젝트에서 "아이콘/버튼을 만들었는데 실제 화면에서 보니 문제"가
라운드7·8·9·11·12로 다섯 번째. 매번 유니코드 글자나 손으로 그린 SVG를 실제 크기로
스크린샷 찍어봐야만 발견되는 문제였다(코드만 읽어서는 안 보임) — 이 프로젝트에서는
"버튼/아이콘 추가" 작업 뒤 스크린샷 자체확인이 사실상 필수 단계로 굳어짐.

**검증 — 실조건검증.** 코랄·다크앰버 두 테마 스크린샷으로 칩 3개(활성 표시 포함)·
얇아진 핸들·사라진 압축 버튼 확인. `view.compact_toolbar` 커맨드 직접 실행으로 로직
회귀 없음 확인(메뉴 클릭 제스처 자체는 미확인).
