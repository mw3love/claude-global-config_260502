주석 상호작용(별도 축, 실제 동작하는 라이브 데모로 비교):

- **하이라이트 — "좋음", 그러나 데모보다 요구가 넓음.** 데모는 텍스트 드래그 하나만
  보였는데, 사용자는 **"텍스트 드래그"와 "자유 사각형(OCR 인식 기반)" 두 도구를 별도
  버튼으로** 요구함 — 자유 사각형도 그 안의 텍스트를 OCR로 인식해서 앵커링해야 함(완전
  자유형 낙서가 아니라 두 경로 다 텍스트 기반).
- **밑줄·취소선 — "좋음", 데모의 단순화를 정확히 지적.** 데모는 시연 편의상 전체 텍스트에
  토글을 걸었는데, 사용자가 "실제로는 드래그한 부분만 적용되어야" 한다고 정확히 짚음(데모
  한계로 정확히 인지, 오해 아님) — 실제 구현은 밑줄·취소선도 하이라이트와 같은 텍스트
  드래그-선택 메커니즘을 공유해야 함. 해제는 ⓐ 같은 도구 버튼 재클릭(토글) 또는 ⓑ 선택
  도구로 그 주석을 골라 삭제, 둘 다 지원.
- **메모(아이콘 숨김+클릭 시 인라인 팝업) — "싫음", 보류.** "이렇게 아이콘으로 숨기는
  메모형식은 일단 필요없음... 다만 문서 위에 작성하는 텍스트 입력이 필요함" — 즉 별도
  아이콘 마커 패턴 자체가 불필요하다는 판정이지, 인라인 편집(팝업 대신 문서에 직접
  쓰기)이라는 방향은 여전히 맞다. 실질적으로 이 요구는 기존 "텍스트 상자(freetext)"
  도구와 겹친다 — freetext가 이미 팝업(`QInputDialog`) 방식이라 같은 문제를 안고 있으므로,
  note를 별도로 개선하는 대신 **freetext를 인라인 편집으로 고치는 쪽에 이 요구를 흡수**하는
  방향으로 다음 구현 라운드에서 검토.
