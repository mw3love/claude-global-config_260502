# Shorts Deck — 디자인 취향 로그

프로젝트: `Shorts_Eng_260903`, `prototype.html`(Artifact 목업, 아직 `public/index.html` 미반영).
배경: 개인용 영어 표현 복습 쇼츠앱. 다크 테마, 코랄(#FF8F6B) 단일 강조색.

## 라운드 1 — 하단 시트(모아보기) 달력 (2026-09-04, 진행 중 · 미확정)

**대상**: 하단 시트의 달력 그리드만(제목/본문 리더 화면은 이번 라운드 밖).
**구성**: Claude 라이브 CSS 3안(C1 절제형·C2 카드형·C3 미니멀 라인형) + 게이트웨이 이미지 2안
(G1 Gemini 주간스트립형·G2 GPT-image 숫자강조형), Artifact `db` capability로 좋음/싫음/애매+의견
인라인 위젯 기록.

**결과**:
- **C2(카드형·둥근모서리+그림자) — 좋음**: "선택한 날짜에 코랄색 테두리가 좋고 각 일자 모서리가
  뭉툭해서 좋네." → 코랄 테두리(기존 확정 원칙과 일치)와 **둥근 모서리**가 긍정 요인으로 명시됨.
  ⚠ 그림자/입체감(elevation) 자체가 좋았다는 언급은 없음 — `preferences.md`의 elevation 가설을
  이 결과만으로 승격시키지 말 것(아직 1개 프로젝트 근거, Easy CAD와 합쳐도 근거가 간접적).
- **C3(미니멀 라인형·헤어라인만) — 좋음**: "큰 숫자 텍스트가 가장 깔끔해서 가독성이 좋네." →
  배경/카드 없이도 가독성엔 문제없다는 신호. "화려함보다 절제" 기존 확정 취향과 일치.
- **C1(절제형·flat 배경만) — 애매**: "일자간 네모는 있는데 붙은 느낌. 구분이 명확하지 않음." →
  칸 배경색만으로는 구분이 약함 → 그림자든 헤어라인이든 **뭔가 시각적 구분 장치가 필요**하다는
  뜻으로 읽힘(C2/C3가 좋은 평가 받은 것과 일관).
- **G1(Gemini 주간스트립) — 싫음**: "이건 뭐 일자가 하나도 없네." (이미지 생성 결함 — 생성 직후
  자체확인에서도 레이아웃 불균형을 이미 인지했었음)
- **G2(GPT-image 숫자강조) — 싫음**: "쓸데없이 공간낭비가 심함."
- **AI 이미지 두 안 모두 탈락** — 이 프로젝트(숫자·격자가 정밀해야 하는 UI)에는 라이브 CSS
  쪽이 처음부터 더 적합했을 가능성. 다음 라운드부터는 게이트웨이 이미지 안을 기본 포함하지
  말고, 필요할 때만(예: 완전히 새로운 레이아웃 아이디어가 필요할 때) 선택적으로 추가.

**미확정 상태로 라운드 종료**: 사용자가 "제목·본문 크기 등 나머지 부분까지 포함해서" 스코프를
넓히자고 요청 → 이 라운드는 최종 확정 없이 더 큰 라운드에 흡수됨. 위 신호(테두리+둥근모서리
긍정, 붙어보이는 flat 배경 부정, 가독성 좋은 큰 숫자 긍정)는 다음 라운드의 캘린더 축에
이어서 반영.

## 라운드 2 — 병합 캘린더 확인 + 글자크기 조절 바 (2026-09-04, 확정)

**대상**: 라운드 1의 C2(둥근모서리+그림자+코랄테두리)·C3(큰 숫자 가독성) 장점을 하나로 합친
캘린더 확인 + 글자크기 조절 바(제목/본문 슬라이더) 2안 비교.

**결과 — 둘 다 확정**:
- **캘린더 병합안 — 확정(수정 1건)**: "다만 큰 숫자(n개 봄) 볼드만 빼면 좋을듯." → 구조·색·
  모서리·그림자는 그대로 확정, **개수 숫자의 font-weight만 650(볼드)에서 낮춰야 함**(값은
  다음 라운드 없이 일반 굵기 400~500 정도로 코드 반영 시 바로 적용 — 별도 비교 불필요할
  만큼 작은 조정).
- **슬라이더 바 — S1(숫자만 표시) 확정, S2(실시간 미리보기) 탈락**: "깔끔하네 어짜피 설정창
  켜도 위쪽에 제목이랑 본문 보이니까 그걸로 확인하면 될듯." → **실제 앱 레이아웃에서는 설정
  시트가 열려도 카드 제목·본문이 화면 위쪽에 그대로 보이는 구조라, 시트 안에 별도 미리보기
  텍스트를 또 넣는 게 중복이라는 지적.** 목업(시트만 뚝 떼어 보여줌)이 실제 앱의 레이아웃
  맥락을 못 보여줘서 생긴 판단 — 이번엔 사용자가 직접 그 맥락을 채워서 판단해 줌.

### 확정 토큰(라운드 1+2 종합)
| 요소 | 값/방식 |
|---|---|
| 캘린더 칸 | `border-radius:10px`, `background:linear-gradient(180deg,var(--ink3),var(--ink2))`, `box-shadow:0 1px 2px rgba(0,0,0,.35),0 3px 8px rgba(0,0,0,.25)` |
| 캘린더 개수 숫자 | `font-size:14.5px`, **`font-weight:400~500`(650에서 낮출 것 — 라운드2 확정 수정사항, 아직 코드 미반영)** |
| 오늘 칸 | `box-shadow:0 0 0 1.5px var(--coral),0 2px 8px rgba(255,143,107,.3)`, 숫자만 coral |
| 글자크기 슬라이더 | 지금 방식(숫자 % 표시) 유지. 트랙만 pill(둥근 alt)+coral 채움으로 다듬기. 실시간 미리보기 텍스트는 추가하지 않음 |

✓ **`prototype.html`에 반영 완료(2026-09-04, 라운드3에서 재확정)** — 아래 라운드3 참조.

## 라운드 3 — 캘린더 원점 재검토(제약 없이 재비교) + 최종 확정 (2026-09-04, 확정)

**대상**: 사용자가 "제한 없이 처음부터"를 요청 — 캘린더 8안(C1 기존안 포함)+AI 무드보드 2안,
슬라이더 6안(S1 기존안 포함)을 새로 뽑아 비교. 캘린더는 그리드를 벗어난 리스트형(C8)까지,
슬라이더는 세그먼트·스테퍼·세로형까지 레이아웃 자체를 흔든 안 포함.

**결과 — 캘린더는 요소별로 3안을 조합, 슬라이더는 기존안(S1) 유지**:
- **칸 모양 = C2(플랫 미니멀)**: 그러데이션·그림자 없이 `background:var(--ink3)` 단색,
  `border-radius:5px`. 라운드1의 카드형(그림자+그러데이션, 라운드1+2 구버전 확정안)보다
  더 단순한 쪽을 최종 채택 — "화려함보다 절제" 기존 확인된 취향과 일치.
- **오늘 칸 테두리 = C1(코랄 링+글로우)**: `box-shadow:0 0 0 1.5px var(--coral),0 2px 6px
  rgba(255,143,107,.3)`. C2 자체의 배경틴트 방식(`color-mix` 채움)보다 테두리 링 쪽을 채택.
- **개수 숫자 = C3(뚜렷하게)**: "학습카운트 숫자는 c3처럼 뚜렷하게"라는 명시적 요청 →
  `font-size:14px;font-weight:300;color:var(--paper)`(밝은 흰색). 라운드1+2에서 확정했던
  "개수는 중립 무채색(muted 회색)" 방향을 이번에 밝은 흰색으로 교체 — 여전히 코랄(강조색)은
  아니라서 "강조색은 의미 있는 상태에만" 원칙 자체는 안 깨짐, 다만 그 안에서도 "뚜렷함"을
  요구한 것.
- **슬라이더는 기존 S1(숫자만 표시+pill 트랙) 그대로 유지** — S2~S6(실시간 미리보기·세그먼트·
  아이콘전용·스테퍼·세로형) 전부 탈락, 이유 언급 없이 "슬라이더는 현재 유지"로 짧게 확정.

**탈락**: 캘린더 C4(히트맵 강도)·C5(도트)·C6(뉴모피즘)·C7(링 진행형)·C8(리스트형 이탈)·
AI 무드보드 2안(히트맵·스트릭뱃지 스타일) 전부 미채택. 별도 사유 언급 없이 3요소(C1/C2/C3)
조합으로 바로 수렴 — 그 외 안들에 대한 구체적 거부 사유는 확보되지 않음(다음에 캘린더를
또 흔들 일이 생기면 이 목록부터 재탐색 대상에서 낮은 우선순위로 둘 것).

**교훈**: "제약 없이 처음부터"로 크게 벌린 라운드였지만, 실제 확정은 기존에 이미 검증됐던
개별 요소(C1 테두리, C2 모양, C3 숫자)를 새로 섞는 선에서 끝남 — 완전히 새로운 레이아웃
패러다임(C8 리스트형 등)까지는 채택되지 않았다. 다음에 "원점 재검토"를 또 요청받으면, 새
콘셉트 자체보다 "기존 확정 요소들의 재조합"에 먼저 무게를 두는 편이 수렴이 빠를 수 있음.

### 탈락 후보와 이유
- **AI 이미지 시안(G1·G2, 라운드1)** — 둘 다 "싫음"(레이아웃 결함·공간낭비). 숫자·격자가
  정밀해야 하는 UI엔 라이브 CSS가 처음부터 더 적합했을 가능성 → 다음 라운드부터 게이트웨이
  이미지는 기본 포함하지 말고 필요할 때만 선택적으로.
- **C1 절제형(라운드1)** — "애매", 칸 배경색만으론 구분이 약함("붙은 느낌") → 그림자·모서리
  같은 시각적 구분 장치가 필요하다는 근거로 라운드2에서 C2 구조 채택에 반영됨.
- **S2 실시간 미리보기(라운드2)** — 목업 단독으론 그럴듯했지만, 실제 앱 레이아웃(제목·본문이
  화면 상단에 항상 보임)에서는 중복 기능이라 탈락. **교훈: 시트만 따로 뗀 목업은 실제 화면
  맥락을 가려서 판단을 오도할 수 있다** — 다음에 시트류 요소를 비교할 땐 가능하면 실제 상위
  화면 맥락(리더 화면 상단)도 같이 보여주는 게 나음.
