## 확정 (2026-09-04, 팔레트 1라운드 — 중립색 색조)

**문제 제기**: "어두운 영역에도 코랄끼가 있다" — `--bg`/`--panel`/`--border`가 강조색(`--accent`,
코랄 `#e08361`)과 같은 따뜻한 색상군으로 틴트돼 있었음. 코드 조사 결과 `--accent`가 57곳에
쓰여 배경 전반의 "흔한 코랄" 인상에 기여.

**진행**: Claude 라이브 CSS로 실제 컴포넌트(상단 사이트탭·좌측 서브탭·구분선·위젯카드·알람행)
조각을 그대로 재현해 후보 비교(게이트웨이 이미지는 이 라운드에선 스킵 — 감시운용PC에
`JBNU_GATEWAY_API_KEY` 미설정, 실제 레이아웃을 정확히 반영해야 하는 비교라 라이브 CSS가
어차피 더 적합했음). 강조색은 전 라운드 고정, 중립색만 변경(한 축 원칙).

**1라운드 (색상군 자체)** — 그래파이트(완전 무채색) / 슬레이트(차가운 청회색) / 차분한 세피아
(원래 계열 채도만 낮춤) 3안 + 기준점. **슬레이트 채택** — "코랄색이 더 돋보여서 좋다"
(보색 대비 효과를 사용자가 스스로 짚음).

**2라운드 (냉색 강도)** — 슬레이트 방향 안에서 옅게(B1)/1라운드 값 그대로(B2)/짙은 네이비(B3)
3단계 비교. **B1(옅게) 채택** — "깔끔하고 좋다". 1라운드의 "돋보임"보다 절제된 인상이 최종
기준이 됨 — 대비 강도는 약한 쪽을 선호(`preferences.md`의 "화려함보다 절제" 항목과 일치,
2번째 프로젝트 확인으로 그 항목을 가설에서 확인됨으로 승격시킨 근거이기도 함).

**최종 검증**: 확정 후보 위에 기존 의미색(경고 주황 `--warn`, 위험 로즈 `--danger`, 이상탐지
마젠타 `--anomaly`)을 함께 배치해 서로 구분되는지 확인 — 그대로 확정.

### 탈락 후보와 이유
- **그래파이트(완전 무채색)** — 1라운드에서 판정 안 됨(암묵적 탈락, 슬레이트가 명시적으로
  선택됨).
- **차분한 세피아(원래 계열 채도만 낮춤)** — 1라운드에서 판정 안 됨(암묵적 탈락).
- **B2(슬레이트, 1라운드 값 그대로)** — 2라운드에서 판정 안 됨. "돋보임" 자체는 긍정적으로
  평가했었지만 더 옅은 안이 나오자 그쪽으로 이동 — 대비가 강할수록 좋다는 뜻은 아니었음.
- **B3(짙은 슬레이트/네이비)** — 2라운드에서 판정 안 됨. 냉색이 너무 강해지면 배경 자체가
  존재감을 가져 코랄과 주목도를 다툴 수 있다는 우려가 사전에 있었고, 결과적으로도 선택받지
  못함.

## 진행 중 (2026-09-04, 입체감 elevation 라운드 — 판정 대기)

`preferences.md`의 Material 스타일 선호 가설(Easy CAD 단일 출처)이 이 프로젝트에서도 성립하는지
판정받는 라운드. 카드 수십 개가 동시에 깔리는 감시용 대시보드 특성상 강한 그림자가 노이즈가 될
수 있다는 우려도 같이 판정 대상.

**후보 구성**: Claude 라이브 CSS 3안(실제 마우스 hover 가능) + gpt-image-2 무드보드 2안.
- C1 평면(지금 방식, 기준점) — 테두리 1px만, 그림자 없음.
- C2 은은한 입체 — 패널을 한 단(`#22262d`) 밝히고 옅은 그림자, 호버 시 2px 상승.
- C3 강한 입체(Material) — 패널을 두 단(`#282d35`) 밝히고 테두리 제거, 진한 다층 그림자,
  호버 시 4px 상승+확대.
- G1/G2 — gpt-image-2로 "은은한/강한 입체감" 무드보드 각 1장(참고용).

**다크 배경에서의 함정(실측)**: 배경(`#14161a`)이 이미 거의 검정이라 그림자만으로는 층이 거의 안
보인다 — Material Dark 스펙대로 **패널 표면 자체를 단계적으로 밝히는 것**을 그림자와 병행해야
실제로 읽힌다. C2/C3의 패널색 차이가 그래서 있다.

**게이트웨이 이미지의 한계(정직하게 페이지에 명시함)**: gpt-image-2가 "은은한"/"강한" 그림자
강도를 문장 지시만큼 정밀하게 구분해 그리지 못했다(G1/G2 육안으로 유사) — 이 축의 정밀 판정은
라이브 CSS(C1~C3)로 하고, 게이트웨이 이미지는 분위기 참고로만 쓰라고 페이지에 직접 밝혀 뒀다.

**대량 배치 테스트**: 카드 10개 그리드를 C1↔C2↔C3 버튼으로 전환하며 "잡음이 되는지"를 그 자리
에서 확인할 수 있게 만듦(별도 정적 스크린샷 3장이 아니라 토글 인터랙션 하나로).

**Artifact**: `https://claude.ai/code/artifact/924c39fc-fbf1-4584-b6ce-3151e2046420`
(favicon 🎚️, "위젯 카드 입체감"). **아직 사용자 판정 전** — 다음 세션에서 이어갈 것.
확정되면 이 파일에 확정 토큰(그림자 값·패널색 hex·호버 반응)을 추가하고, 코드 반영은 별도 작업.

⚠ **작업 중 실측한 함정 2건(재사용 가치, 여기 기록)**:
- `text-wrap: balance`가 아니라 **IBM Plex Mono에 한글 글리프가 없어서** 폴백 시 음절 사이
  간격이 들쭉날쭉해지는 버그였다("위젯"이 "위 젯"으로 벌어짐) — 처음엔 balance를 의심했으나
  무관했다. 한글 섞인 헤딩엔 모노스페이스 폰트 스택을 쓰지 말 것(순수 라틴/숫자 라벨에만).
- Artifact 안 CSS 셀렉터 특정도 동률 함정 — 뒤에 선언된 규칙이 이긴다는 걸 잊고 `.mcard`
  변형 클래스를 앞서 선언했다가 스타일이 안 먹은 적 있음(이번엔 순서를 맞춰 회피).
