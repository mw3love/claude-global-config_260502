**컴포넌트 원칙**

- Primary 버튼(예: 저장): **아이콘 + 텍스트 결합**(아이콘 단독 금지).
- 토글(예: 스냅): **텍스트 라벨 + 체크마크** 형태(점만 있는 슬라이더 금지).

**코드 반영 — 1차 완료(2026-08-02)**: accent를 코랄(#da7756)로 교체(`_dark_palette()`

:hover/:pressed 강제 시도했으나 반영 안 됨 — 이 앱 특성상 실제 창에서만 확인 가능, pitfalls.md

**다음 단계**: 토글(스냅 등)의 "텍스트 라벨 + 체크마크" 표현은 현재 아이콘 전용 QToolButton이라
별도 커스텀 위젯이 필요 — 아직 미착수.

**checked 상태 재조정(같은 날 2차 피드백)**: 1차는 hover/checked/pressed 전부 "배경 틴트"였는데,
실사용 확인 후 "checked가 불투명한 사각 블록처럼 보인다"는 지적으로 배경 없이 **테두리만**으로
1차 수정. 그런데 스냅·격자(기본값 ON)·좌측 「도형」 탭(둘 중 하나 상시 선택)처럼 **평소에도
계속 켜져 있는 토글**에 테두리 박스가 상시 떠 있으니 이번엔 "항상 튀어 보인다"는 재지적 —
순간적 강조(그리기 도구 무장·핀 on)엔 테두리가 맞지만, 상시 상태엔 안 맞았던 것.
**최종 확정**: checked = 테두리 없이 **옅은 배경 틴트만**(`rgba(218,119,86,35)`, hover의
alpha 40보다도 낮음) — 박스처럼 도드라지지 않으면서 "켜짐"은 계속 알림. hover/pressed는
건드리지 않음(순간 피드백이라 진한 게 맞음, hover 40+테두리·pressed 150+테두리 유지).
**교훈**: "checked(상시 지속 가능) 상태"와 "hover/pressed(순간적) 상태"는 같은 강도의 강조를
쓰면 안 된다 — 순간 상태에 맞는 강한 표현(테두리·진한 배경)을 지속 상태에 그대로 쓰면 화면이
상시 소란스러워진다. 다음에 토글류 상태를 디자인할 땐 "이게 평소에도 계속 ON일 수 있는가"를
먼저 따져서 강도를 달리 정할 것.

**hover 테두리도 제거(같은 날 3차, 위와 이어서)**: checked가 무테두리가 되니 이번엔 hover만
테두리가 남아 상대적으로 더 튀어 보였다 — hover도 테두리 없이 **checked보다 옅은 배경 틴트**
(`rgba(218,119,86,25)`, checked의 35보다 낮음)로 낮췄다. 완전히 없애는 안도 검토했으나
기각 — 아이콘 전용 툴바라 hover가 유일한 즉각 피드백(툴팁은 딜레이 있음)이고, hover는 커서가
그 자리에 있는 동안·한 번에 하나만 켜지는 순간적 상태라 checked만큼 소란스러울 걱정은 적어
"완전 제거"보다 "옅게 유지"가 낫다고 판단(사용자 확인). pressed는 여전히 진한 배경(150)+
테두리 유지 — 클릭 확정 피드백은 또렷해야 함.
**최종 3단계 강도**: hover(25, 순간·발견용) < checked(35, 지속·상태 표시) < pressed(150+테두리,
순간·확정 피드백) — 지속 상태(checked)가 순간 상태(hover)보다 살짝 진한 게 자연스럽다(하나는
"이게 지금 선택돼 있다"를 계속 말해야 하고, 하나는 "커서가 지나간다"만 알리면 된다).

**hover를 코랄에서 중립 회색/검정으로 전환(같은 날 4차)**: hover까지 코랄 틴트로 남기니
"이미 아이콘·checked·구분선이 전부 코랄인 화면에서 hover까지 코랄이면 코랄이 흔해져서
checked(진짜 선택됨)의 신호력이 떨어진다"는 지적 — 사용자가 직접 이 방향을 제안. hover는
의미 없는 발견용 신호(클릭 가능 여부만 알리면 됨)라 색을 뺐고, checked는 "지금 활성 상태"라는
실제 의미가 있으니 코랄을 그대로 유지(색 있는 요소는 checked/pressed로 좁혀짐).
최종: `QToolButton:hover { background: rgba(255,255,255,22) }`(다크, 배경을 밝히는 흰색 계열) /
`rgba(0,0,0,18)`(라이트, 배경을 어둡히는 검정 계열) — 밝은 배경 위에 흰 틴트를 얹으면 안 보여
방향을 테마별로 뒤집었다. **교훈**: 액센트 컬러가 화면 전체(아이콘·강조선·checked)에 이미
많이 쓰이고 있다면, **모든 상호작용 피드백에 그 색을 쓰지 말고 "의미 있는 상태"(checked/
selected)에만 아껴 써야** 그 색이 신호로서 계속 기능한다 — 발견용 피드백(hover)은 중립색이
표준적이고 더 조용하다.

**아이콘 자체도 코랄 → 중립색으로 전환, checked를 2단계로 분리(같은 날 5차)**: hover 색을
바꾼 뒤에도 아이콘 자체(18종 SVG, 코랄 고정)가 여전히 상시 코랄이라 사용자가 "상단 도구들
색을 도형 팔레트처럼 흰색으로" 요청 — 도형 팔레트(`_shape_icon`)는 원래부터 테마 적응
중립색(다크 `#cdd8e3`/라이트 `#39434f`)이었으므로 상단바 아이콘도 그 값으로 통일. 코랄은
이제 "버튼 배경 틴트"(checked/hover/pressed)로만 남는다.
같이 요청된 것: "클릭 뗀 후에도 pressed 수준(alpha 150)의 진한 코랄을 고정색으로 유지"하되
"상시 ON일 수 있는 항목(스냅·격자)은 제외" — 순간적으로 켜지는 항목(그리기 도구 무장·핀·
직교)만 pressed와 같은 강도(150+테두리)를 checked에도 적용, 스냅·격자는 기존 옅은 35 그대로
유지. 구현은 `QToolButton#toolStrongCheck:checked`(objectName 선택자, CSS 명시도로 일반
`QToolButton:checked`를 이김)를 순간 그룹에만 부여 — 별도 stylesheet를 각 위젯에 거는
방식(조상↔자손 캐스케이드에 기대야 함) 대신, 같은 stylesheet 문자열 안에서 선택자 명시도로
가르는 쪽이 결과가 항상 결정적이라 이쪽을 택함.
**최종 규칙 정리**: 아이콘 색 = 항상 중립(코랄 없음). 코랄은 버튼 배경 상태 전용, 그 안에서도
"상시 지속 가능(35)" vs "순간적 활성(150+테두리, pressed와 동일)" 2단계.

⚠ **세그폴트 부작용 발견·해결** — 아이콘 재칠(코랄→중립색) 구현 중 `QPainter.
CompositionMode_SourceIn`을 쓴 첫 버전이 스모크 테스트(`test_easycad.py`, 짧은 시간에
CanvasWindow 수십 개 생성) 중 재현 가능한 네이티브 세그폴트를 일으켰다. 합성모드를 아예
안 쓰고 `QImage.setPixelColor()` 픽셀 루프로 바꿔 해결 — 이 프로젝트에서 앞으로 아이콘/
이미지 재칠이 또 필요하면 **QPainter 합성모드(SourceIn/DestinationIn) 대신 픽셀 루프를
기본으로 고려할 것**. 상세: `docs/pitfalls.md` "렌더링" 항목, wiki
`easycad-svg아이콘재칠-QPainter합성모드-세그폴트.md`.

아이콘이 전부 얇은 단색 라인아트였던 것. 겸사겸사 "그리기도구=현재 그리기색 반영" 관례를
프레임챌린지로 재검토 → **실제로 안 쓰는 기능으로 확인, 폐기**. 그리기도구/액션도구 색상 구분
없이 전부 통일 스타일로 감.

**스타일 확정**: **A2 "듀오톤"** — 코랄(#da7756) 얇은 외곽선 + 아이콘마다 의미 있는 한 부분만
코랄 단색 채움(포인트). 몸체 전체를 흰색으로 채우는 안(A3)은 비교 후 탈락 — "일부만 강조 채움"
쪽이 더 낫다고 판단.
- SELECT: 커서 꼬리 부분만 코랄 채움
- ARROW: 화살촉 삼각형만 코랄 채움
- TEXT: 밑줄만 코랄 채움
- **SAVE는 예외** — 기본 A2(위 슬롯 채움/아래 라벨칸 빈 테두리) 대신 **위·아래를 반전**(위
  슬롯=빈 테두리, 아래 라벨칸=코랄 채움)한 S2 버전으로 확정. 이유: 3안(S1 원본/S2 반전/S3
  아래만 흰색 채움)을 나란히 비교한 뒤 반전이 더 낫다고 판단.
- 입체(아이소메트릭 3D, B그룹) 스타일은 탈락 — 듀오톤이 더 낫다고 판단됨.

**라이트 테마 색 — 사용자 확정**: 다크/라이트 둘 다 코랄(#da7756) 고정(테마 무관, 재칠 없음).
검토했던 대안(라이트만 기존 블루 accent로 스왑/라이트는 구 아이콘 유지)은 기각 — "브랜드
일관성이 대비 미세 차이보다 우선"이라는 판단. 흰 배경에서도 렌더 확인 결과 대비 충분.

**아키텍처**: SVG는 코랄 색을 파일에 직접 인코딩(런타임 재칠 없음, currentColor 미사용) —
`core_constants.py`의 `_svg_icon_pixmap()`/`_svg_icon()`(QSvgRenderer 기반, 결과 캐시)이
공유 로더. `_tool_icon(tool)`은 이제 이름 하나만 받아 그대로 위임(색 인자·중립색 인자 제거 —
"그리기도구=현재 그리기색 반영" 관례 폐기에 따라 draw-color 트래킹 코드 전부 삭제).
`_act_icon(name)`은 상단바 노출 11종만 SVG로 라우팅하고, 메뉴 전용 8종(pdf/image/table/
titleblock/mermaid/zoom_fit/zoom_100/align)은 이번 라운드 스코프 밖이라 기존 QPainter 코드
그대로 유지 — 다음에 메뉴 아이콘도 이 스타일로 옮길 땐 그 8개가 대상.
PyInstaller 번들링: 이 프로젝트는 아직 패키징 안 함(스펙 파일 없음) — `_icons_dir()`가
`sys._MEIPASS` 분기를 미리 넣어놔 나중에 패키징 붙을 때 추가 작업 없이 그대로 동작.

⚠ **발견(미수정, 스코프 밖)**: `_act_icon("align")`(정렬 가이드선 메뉴 액션)이 처음부터
빈 투명 아이콘이었다(모든 QPainter 분기에서 "align" 이름을 처리하는 case가 없음) — 이번
작업과 무관한 기존 버그, 코드는 안 건드림.
