# memory 구조 정리 — 어디부터 손댈지 결정

생성: 2026-09-02 08:51

## 배경

한 달 전 만든 `autoMemoryDirectory` 기반 memory 동기화 설정(`session-memory-hook.py` +
`repos.json`)이 잘 작동하는지 점검 요청으로 시작한 세션. 실측 결과:

- 이 PC(`MW-Samsung26`)에서 정상 작동 확인 — `session-memory-hook.log`에 최근 세션 기록,
  각 repo `.claude/settings.local.json`에 `autoMemoryDirectory` 실제 반영, `memory-sync-hook.py`
  (SessionEnd)의 `auto(memory): ... 동기화` 커밋 연속 확인, `git status` 클린.
- 2026-08-26 감시운용PC(`Dev-Mw\` 폴더 배치가 `repos.json`의 `Dev/`와 안 맞아 11개 중 8개
  매칭 실패)에서 발견된 사고는 commit `1af8ae7`로 이미 수정됨(경로 실패 시 git remote URL →
  폴더명 순으로 폴백).
- **미확인 채로 남은 것**: 그 사고로 감시운용PC에 2주치 쌓였던 stranded 데이터
  (`~/.claude/projects/<경로키>/memory/`, git 제외 위치)를 새 구조로 백필했다는 커밋을
  `git log --all --grep`으로 못 찾음. 그 PC를 직접 열어봐야 확인 가능(이 PC에선 불가).

## 이어서 나온 근본 질문과 결론

사용자가 "프로젝트 대부분을 git으로 관리하는데, 왜 memory를 전역에 몰아넣나 — 각 프로젝트
문서에 개별 정리하는 게 맞지 않나?"를 제기. 대화로 파고들어 실측으로 검증한 결론:

**1. 클로드코드 기본 memory 저장 위치의 성질** (`~/.claude/projects/<경로파생키>/memory/`):
- `.gitignore`의 `/projects/`로 원래부터 제외됨(확인: `~/.claude/.gitignore` 21번째 줄).
- 폴더명이 절대경로를 그대로 변환한 것(`C--Users-KBS--claude` 등) → PC마다 사용자명·드라이브가
  다르면 폴더명도 달라져 **애초에 git으로 동기화해도 하나로 안 합쳐짐** (실측: 이 PC에
  8개 폴더 확인, 각각 로컬 경로 기반 이름).
- 대화 전체 로그(`.jsonl`)도 같은 폴더에 같이 들어있어(실측: `C--Users-KBS--claude` 안에
  `memory` 서브폴더 옆 `.jsonl` 파일 4개 확인) 통째로 git 추적하기도 부적절(용량·프라이버시).

**2. 그래서 만든 우회(`autoMemoryDirectory` 리다이렉트)가 해결한 것과 안 한 것**:
- 해결: "서랍(프로젝트별 memory 버킷) 위치를 `~/.claude` 안으로 옮겨서 기존 git 동기화를
  태우는 것" — 여기까지가 지난달 작업.
- 안 해결: "서랍 안에 뭘 넣을지"(그 프로젝트 고유 사실 vs 프로젝트와 무관한 전역 사실)를
  가르는 것. 네이티브 memory 도구 자체가 "지금 연 프로젝트 서랍"에 무조건 쓰기 때문에,
  글로벌 규칙(10-c, 8/26 도입: "프로젝트 사실은 memory 대신 그 repo에")이 있어도 **내용
  종류와 무관하게 일단 그 프로젝트 서랍으로 감**.

**실측 증거** (`Easy_CAD_260718`의 `memory/projects/Easy_CAD_260718/` 폴더를 열어 확인):
| 파일 | 문제 |
|---|---|
| `dialog-crash-fasoo-drm-hook.md` | 프로젝트 고유 사실(QThread 크래시 원인)인데 이미 그 repo의 `docs/pitfalls.md`·`docs/history/2026-08*.md`에 같은 내용이 중복 존재 |
| `claude-code-skill-overrides.md` | 프로젝트와 무관한 전역 사실(클로드코드 `skillOverrides` 기능)인데 그 프로젝트 세션에서 나왔다는 이유만으로 프로젝트 서랍에 갇힘 |
| `feedback_no_superpowers.md` | 마찬가지로 무관한 전역 사실(플러그인 삭제)이 프로젝트 서랍에 갇힘 |

## 다음 세션에서 결정할 것 — 4가지 옵션 (사용자가 아직 안 골랐음, 처음부터 다시 제시할 것)

1. **규칙만 고치기(내가 추천)** — 전역 `CLAUDE.md` 규칙 10-c를 "프로젝트 무관 사실은 지금
   열린 프로젝트 서랍이 아니라 진짜 전역 루트(`~/.claude/memory/`)에 써라"까지 명시하도록
   다듬는다. 기존 파일은 안 건드림, 가장 작고 리스크 없는 변경.
2. **1 + Easy_CAD 3개 파일 실제 정리** — 규칙을 고친 뒤, 위 3개 파일로 실제 적용해 패턴을
   검증한다(`dialog-crash-fasoo-drm-hook.md`는 삭제하거나 요약만 남기고 `pitfalls.md`로
   통합, 나머지 2개는 전역 루트로 이동).
3. **전체 프로젝트 감사** — `repos.json`에 있는 모든 프로젝트의 `memory/projects/*`를
   같은 기준으로 전수 정리(2번의 확장판, 시간 오래 걸림).
4. **구조 자체 변경(더 큰 결정, 별도 논의 필요)** — `autoMemoryDirectory`를 `~/.claude`
   대신 각 프로젝트 repo 안(`<repo>/.claude/memory/`)으로 돌리는 안. `repos.json` 경로
   매핑이 아예 불필요해지지만(`git rev-parse --show-toplevel`로 즉석 계산), 지금
   `~/.claude` 하나에만 허용한 "확인 없이 자동 commit+push"를 다른 프로젝트 repo들로도
   넓혀야 하는지가 별도 결정 필요(팀 repo 여부 등 repo마다 위험도가 다름).
