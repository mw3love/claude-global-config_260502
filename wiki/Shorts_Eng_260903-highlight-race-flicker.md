# 낙관적 업데이트 연타 시 깜빡임 — 요청 큐 직렬화만으론 못 잡는다

## 함정

버튼/드래그로 상태를 토글하는 기능(형광펜 온오프)에서 fire-and-forget 패턴을 쓰다가
"연타하면 화면이 잠깐 깜빡인다"는 신고를 받음. 1차 진단: 요청 A(느림, ~150ms)와
요청 B(빠름, ~20ms)를 거의 동시에 보내면 B의 응답이 A보다 먼저 도착해 화면이 잘못된
순서로 갱신될 거라 보고, 다른 토글 기능(known/archive/trash)에 이미 있던
`flagQueue.then(run, run)` 패턴(요청을 순차로만 보내는 큐)을 그대로 재사용해 고쳤다고
생각했다.

**하지만 재현 결과 여전히 깜빡였다.** 최종 상태는 항상 맞는데(직렬화 자체는 성공)
"시작과 끝 사이"에 화면이 한 번 흔들리는 게 남아 있었다. 원인은 큐가 **요청을 보내는
순서**만 보장했지, **각 응답이 도착할 때마다 여전히 전체 재렌더를 하는 것** 자체를
막지 못했기 때문 — A를 먼저 보내고 B를 나중에 보내도(직렬화 성공), A의 응답이
도착하는 시점엔 이미 B가 낙관적으로 다른 화면을 보여주고 있는데, A의 재렌더가
"A 시점 기준 정답"으로 화면을 한 번 되돌려버리고, 그 직후 B의 응답이 와서야 다시
최종 모습으로 바뀐다. **요청 순서 보장(큐)과 화면 렌더 순서 보장은 서로 다른 문제다**
— 전자만 고치면 최종 상태는 맞아도 중간 과정의 시각적 흔들림은 남는다.

## 해법

전역 단조증가 카운터(`seq`)를 둬서, 응답을 처리할 때 "이 요청을 보낸 이후 더 최신
요청이 이미 시작됐는지"를 확인하고, 그렇다면 **이 응답으로는 화면을 아예 건드리지
않는다**(서버로 보내는 요청 자체는 그대로 다 나가야 함 — 서버 쪽 최종 상태가
누적적으로 맞아야 하므로 요청 취소는 안 됨). 렌더만 "가장 최근에 시작한 동작의
응답 하나"로 좁히면, 중간 상태를 화면에 아예 노출하지 않으므로 깜빡일 것이 없다.

```js
let seqCounter = 0;
function doAction(...) {
  const seq = ++seqCounter;
  queue(() => api(...).then((res) => {
    if (seq !== seqCounter) return; // 더 최신 동작이 이미 시작됨 — 이 응답은 버림
    // ...정상 렌더...
  }));
}
```

부수로 "그 사이 화면이 다른 대상(다른 카드/다른 아이템)으로 이미 바뀌었는지"도
같이 확인해야 한다 — 늦게 도착한 응답이 지금 화면에 보이는 **다른** 대상의 내용을
옛 데이터로 덮어쓸 수 있다(예: `currentTarget() === capturedTarget` 재확인).

## 대가

렌더를 건너뛴 stale 응답의 `res.card`(또는 동등한 서버 최신 데이터)는 버려지므로,
그 데이터에 화면 갱신 말고 다른 부수효과(예: 로컬 캐시 갱신)가 있다면 그것도 같이
스킵되는지 확인해야 한다. 이 사례에서는 다행히 마지막(최신) 응답이 서버의 누적
최종 상태를 그대로 담고 있어 안전했다 — 서버가 요청을 받은 순서대로 처리해 매
응답이 "그 시점까지의 전체 상태"를 돌려주는 API였기 때문. 응답이 델타(diff)만
돌려주는 API였다면 stale 응답을 건너뛰면 델타 유실이 생기므로 이 패턴을 그대로
못 쓴다.
