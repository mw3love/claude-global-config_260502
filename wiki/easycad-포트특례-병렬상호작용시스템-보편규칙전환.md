# 포트 전용 특례를 상호작용 함수마다 심었다가 3라운드 스턱루프 — 보편 규칙 전환으로 해결

## 함정
포트(호스트 테두리에 부착된 작은 도형)를 호버·선택하면 "장비 전체"처럼 반응해 화살표+새
도형 생성 고스트가 뜨는 버그. "포트는 화살표만, 장비 복제는 안 됨"이라는 요구를 포트 전용
`if getattr(sh, "_port_host", None): ...` 특례로 풀려 했으나 3라운드 연속 실패:

- 1차: 미선택 호버 스캔 함수(`_conn_shapes_near`)에서 포트를 후보 제외 → 포트 *선택* 시엔
  완전히 다른 코드 경로(`_qc_dot_rects`, 선택된 도형의 자체 큐닷)가 살아있어 그쪽에서 같은
  증상 재발.
- 2차: 그 함수에도 포트 예외를 추가 → 이번엔 "4변 접속점은 선택 여부와 무관하게 항상
  있어야 한다"는 요구와 정면충돌(그 함수가 유일한 렌더+히트테스트 소스라 완전히 끄면
  기능 자체가 없어짐).
- 3차: "포트 정중앙만" 죽은 지대로 판정하는 헬퍼를 만들어 세 함수에 심음 → 렌더링을
  담당하는 `_draw_port_dots`는 히트테스트 함수(`_hover_port_at`)가 아니라 **완전히 별도의
  성근 매칭 시스템**(`_port_dot_target`, "근처 도형 하나를 통째로 골라 미리보기")을 쓴다는
  걸 몰라서, 포트 근처를 호버하면 호스트의 동서남북 점이 대신 뜨는 새 버그 발생.

공통 원인: 이 앱의 호버/큐닷 상호작용이 **병렬 시스템 여러 개**(코스 매칭용 프리뷰 선택기,
이산 4점 히트테스트, 선택된 도형 전용 큐닷, 드래그-릴리즈 생성기, 클릭 전용 즉시생성기)로
나뉘어 있어서, "포트냐 아니냐"를 특례로 풀려면 매번 병렬 시스템 개수만큼 예외를 심어야
했다 — 하나 놓치면 그 함수에서 증상이 재발.

## 해법
사용자가 직접 패턴을 지적("복잡성이 늘어서 근본적인 질문")하며 전환 제안: 포트를 특수
객체로 취급하지 말고 **완전히 평범한 도형으로 되돌린 뒤**, "화살표만"이라는 요구를 포트
전용 규칙이 아니라 **전 도형 공통의 보편 규칙 변경**으로 풀 수 있는지 검토.

채택안: "큐닷을 클릭하면 도형 복제(기존과 동일) / 드래그하면 화살표만(신규, 전 도형
공통)"으로 규칙 자체를 바꿈. 빈 캔버스에 드래그해 놓아도 이제 **어떤 도형이든** 복제가
안 생기고 끝이 비어있는(미결) 화살표만 남는다 — 이 규칙 하나가 포트가 원하던 동작을
포트 전용 코드 없이 만족시킨다. 1~3차에서 추가했던 죽은 지대 헬퍼·포트 전용 조기 반환을
전부 제거하니 오히려 코드가 줄었다(순변경 -는 아니지만 특례 지점 0개로 수렴).

## 대가
"포트만 다르게"가 아니라 "전 도형이 다르게" 동작하도록 규칙을 바꾸는 것이므로, 기존
동작(빈 캔버스 드롭 시 도형 자동 복제)에 의존하던 기존 테스트·문서화된 관례를 전부
갱신해야 했다(스모크 4개 재작성). 보편 규칙 전환은 "포트만 고치면 끝"보다 변경 반경이
넓다 — 단, 그 대신 향후 비슷한 특수 아이템이 또 생겨도 특례가 필요 없다는 게 트레이드오프.

## 일반화된 교훈
"이 아이템 종류만 다르게 반응해야 한다"는 요구를 받으면, 먼저 "특수 케이스가 아니라
보편 규칙 변경으로 풀 수 있는가"를 검토한다. 특히 상호작용이 여러 병렬 시스템(호버 프리뷰/
히트테스트/선택 전용/드래그 릴리즈/클릭 즉시생성 등)으로 나뉜 코드베이스에서는, 특례를
하나씩 추가하는 접근이 병렬 시스템 개수만큼 반복 실패를 낳는다.
