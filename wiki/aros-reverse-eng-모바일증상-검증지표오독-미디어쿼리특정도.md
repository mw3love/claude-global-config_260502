# 모바일 증상이 헤드리스에서 "재현 안 됨"으로 나올 때 — 지표를 의심할 것

## 함정

### 1. 검증 지표를 틀리게 잡으면 몇 번을 재현해도 재현이 안 된다 (가장 비쌌던 것)

사용자 보고: "표 **첫 행** 높이가 유독 높다" + "아래쪽 여백이 남는다". 나는 「첫 행」을
**데이터 1행**으로 읽고, 데이터 행들의 높이가 균일한지만 쟀다 → 전부 41.66px로 균일 →
"크로미움에서도 웹킷에서도 재현 안 됨, 실기기 전용 문제" 결론.

이 오독 위에서 추측성 패치를 3번 냈고 전부 빗나갔다:
- 사파리 `position:sticky` + flex 부모 렌더링 버그 가설 → 1단 뷰에서 `display:flex`(.multi-col) 제거
- iOS 주소창 접힘을 `window resize`가 안 알린다는 가설 → `visualViewport` 리스너 추가
- `main` 상하 패딩 축소

사용자가 «첫행(**제목**)»이라고 한 단어를 덧붙인 순간 지표가 바뀌었고, **이미 갖고 있던
측정 데이터 안에 답이 있었다** — thead 56.3px vs 데이터 행 41.7px. 여백도 마찬가지로
`pagerBottom` vs `innerHeight`를 한 번도 안 쟀을 뿐, 재보니 61.1px가 그대로 찍혔다.

교훈: **"재현 안 됨"은 "증상이 없다"가 아니라 "내가 그 값을 안 쟀다"일 수 있다.**
엔진을 바꿔가며 재현을 시도하기 전에, 사용자가 쓴 단어가 내가 잰 대상과 같은지부터 맞춘다.

### 2. 미디어쿼리는 특정도를 올리지 않는다 (한 세션에 3번 반복해서 밟음)

`@media (max-width:720px)` 블록이 파일 **위쪽**에 모여 있었다. 거기에 모바일 오버라이드를
추가하면, 파일 **아래쪽**의 무조건 규칙(같은 단일 클래스 선택자)이 소스 순서로 이겨
**어느 화면 폭에서도 적용되지 않는다.** 증상은 "규칙을 넣었는데 화면이 그대로"다.

실제로 죽어 있던 것들:
- `.ws-fixed-group`/`.ws-dash-group`의 가로 정렬 → 모바일 서브탭이 세로 2열로 쪼개져
  화면 대부분을 네비게이션이 먹고 있었음(수개월간 그 상태였을 가능성)
- `.tab-btn` / `.explore-toolbar` / `.ab-row`의 패딩 축소 → 기대 16px 중 2px만 반영

이 repo의 CSS엔 같은 교훈이 이미 주석으로 박혀 있었는데도(`.widget.size-4x2` 근처)
또 밟았다. **블록의 물리적 위치가 아니라 "이 선택자의 기준 규칙이 어디 있나"로 자리를 정한다.**

### 3. 곁가지 — 0폭 컬럼의 `<th>`가 헤더 행 전체를 부풀린다

`table-layout: fixed` + `colgroup`에서 폭을 안 준 「이름」 컬럼은, 고정폭 합이 컨테이너를
넘으면 **0px로 눌린다**. 데이터 셀엔 `.x-name-cell{overflow:hidden}`이 있어 잘렸지만
`<th>`엔 없어서 헤더 글자만 세로로 접혔고, 행 높이는 가장 높은 셀을 따르므로 헤더 줄
전체가 56px로 부풀었다.

### 4. 곁가지 — floor 나머지는 계산으로 못 없앤다

"화면에 몇 행 들어가나"를 아무리 정확히 계산해도 `floor` 나머지(최대 1행−1px)는 남는다.
행 수 계산을 다듬는 방향으로는 하단 여백이 절대 0에 안 간다.

## 해법

1. **지표 교정** — 헤더 높이 vs 데이터 행 높이, `pager.bottom` vs `window.innerHeight`를
   직접 찍는다. 스크린샷 눈대중이 아니라 `getBoundingClientRect()` 숫자로.
2. **미디어쿼리 배치** — 모바일 오버라이드는 그 선택자의 기준 규칙 **바로 뒤**에 둔다.
   위쪽 720px 블록에는 기준 규칙이 그보다 앞에 있는 것만 남긴다.
3. **`<th>`에도 `white-space:nowrap; overflow:hidden`** — 0폭으로 눌려도 세로로 안 접힘.
4. **자투리는 계산이 아니라 레이아웃으로 흡수** — 표 그릇(`min-height`)을 가용 높이까지
   늘려 페이저를 화면 바닥에 붙인다. 남는 자투리는 표 테두리 «안쪽» 빈칸이 되어 화면
   아래 여백으로 안 보인다. (사용자가 참고로 보내준 다른 앱도 하단 바 고정 구조였다)
5. **레이아웃 안정 후 재측정은 타이머가 아니라 `ResizeObserver`** — 렌더 직후엔 위쪽 요소
   (상태 토스트 등)가 안 자리잡아 표의 top이 22px 틀리게 잡힌다. 지연시간을 추측해 재시도하면
   기기마다 어긋난다. 관찰자로 바꾸되, **값이 같으면 style을 안 건드려야** 되먹임이 안 생긴다.
6. **모바일 검증은 Playwright `webkit`** — `python -m playwright install webkit`. iOS Safari와
   같은 엔진 계열이라 "사파리 전용 버그" 가설을 반증할 수 있다(실제로 반증됐다).
   뷰포트 높이는 844가 아니라 **690 안팎**으로 — 기기 가시높이는 Safari 툴바를 뺀 값이다.

## 대가

- 진동 방지 장치(직전 보정 A→B를 B→A로 되돌리는 것 차단)를 **무기한**으로 걸면, 탭 전환처럼
  레이아웃이 실제로 바뀌어 되돌아가는 것이 정답인 경우까지 막는다 — 실측으로 Digital 탭에서
  페이저가 화면 밖 27px로 밀렸다. **500ms 시간 창**을 둬야 한다(진동은 수십 ms 안에 일어남).
- 표 그릇을 채우는 방식은 자투리를 «없애는» 게 아니라 «옮기는» 것이다 — 표 안쪽에 빈 줄이
  보인다. 그걸 없애려면 행 높이(터치 타깃)를 줄여야 하는데, 이 repo에선 그 값이 예전
  사용자 요청("클릭하기 힘들다")으로 키운 것이라 되돌릴 수 없었다.
