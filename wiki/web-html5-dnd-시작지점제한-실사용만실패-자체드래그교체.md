# 네이티브 HTML5 DnD의 「시작 지점 좁히기」는 실사용에서만 깨지고 격리 검증은 가짜 통과를 준다 — 마우스 이벤트 자체 드래그로 교체

## 함정

위젯 그리드 재배치가 `draggable=true` + `dragstart`/`dragover`/`drop`으로 되어 있었다.
"카드 전체 말고 ⠿ 핸들만 잡는 자리로" 라는 평범한 요구에서 출발해 **네 번 연속 실패**했다.

**핸들 전용화 3방식 — 셋 다 격리 검증 통과, 셋 다 실사용에서 드래그가 죽음:**

1. `dragstart`에서 `e.target`으로 판정 → **`dragstart`의 `e.target`은 실제로 눌린
   자식이 아니라 `draggable=true`가 걸린 조상 자신이 항상 된다.** `e.target.closest('.drag-handle')`이
   핸들을 눌러도 늘 false라 드래그가 통째로 막혔다.
2. `mousedown`에 눌린 좌표를 기록해 `dragstart`에서 읽기 → 격리 환경은 로그까지
   찍어가며 정상 동작하는데 **사용자 실브라우저에서만** 게이트가 닫혔다. 원인 못 좁힘.
3. `draggable`을 핸들 자신에 걸고 `setDragImage(카드)` → 카드가 흐려지기만 하고
   (=`dragstart`는 발생) 이동이 안 됨. 역시 실사용에서만.

**되돌린 뒤 남은 4번째 결함(원인 끝내 미상):** 페이지를 새로 연 뒤 **첫 드래그를
위젯 헤더에서 시작하면 아무 일도 안 일어난다.** 본문(차트 영역)에서 한 번 **드롭까지
완료하고 나면** 그 뒤로는 헤더에서도 정상 작동. 경계는 정확히 `.widget-head` vs
`.widget-body`였고, 헤더의 *텍스트가 아닌 여백*도 똑같이 실패해 "텍스트 드래그로
해석된다" 가설은 기각. 실측으로 기각한 가설이 5개(핸들 3방식 + `user-select:none`
+ `-webkit-user-drag:none`), 여기에 "원격 접속 환경 탓" 가설도 반증됨.

**⭐ 진짜 함정은 「검증 수단이 거짓말을 한다」는 것이다.**

- **실마우스 드래그**(`page.mouse.down/move/up`, `page.drag_and_drop()` 둘 다) →
  헤드리스 Chromium이 네이티브 드래그 세션에 걸려 **자동화 채널째로 멈춘다**
  (실측, 각 60~180초 대기 후 강제 종료). 즉 진짜 조작으로는 아예 확인이 안 된다.
- **합성 `DragEvent` + `dispatchEvent`** → 돌아간다. 그런데 **대상 요소를 인위로
  지정하므로 "브라우저가 드래그를 시작할지 말지 결정하는 단계"를 통째로 건너뛴다.**
  위 실패를 하나도 재현하지 못한 채 **"통과"라는 가짜 신호**를 준다.
  → 세 번의 실패가 전부 "격리 검증 통과 → 실사용 실패"였던 이유가 이것이다.

## 해법

**원인 규명을 포기하고 메커니즘째 교체 — 네이티브 DnD를 버리고
`mousedown`/`mousemove`/`mouseup` 기반 자체 드래그로.**

⭐ **이 방식을 고른 결정적 이유는 "이번엔 다를 것"이 아니라 「이번엔 검증할 수 있다」였다.**
자체 드래그는 브라우저의 드래그 세션에 애초에 안 들어가므로 헤드리스가 멈추지 않고,
Playwright 실마우스 조작으로 끝까지 재현된다. 실제로 39항목을 한 번도 안 멈추고 돌렸고
사용자 실브라우저에서도 첫 시도에 정상 동작했다(그전 3번은 전부 실사용에서 깨졌다).

**교체 시 직접 챙겨야 하는 것 — 네이티브가 공짜로 주던 것들:**

- **드래그 이미지** → 원본을 `cloneNode(true)` 해 `position:fixed`로 커서를 따라가게.
  ⚠ **복제본의 `id`를 전량 제거**할 것 — 안 그러면 중복 id 때문에
  `getElementById(...)`가 복제본을 집어, 주기적 갱신 로직이 화면이 아니라
  미리보기에 값을 써 넣는다.
  ⚠ 복제본에 `pointer-events: none` 필수 — 없으면 미리보기 자신이 커서 아래
  최상단 요소가 되어 `elementFromPoint` 히트테스트가 늘 자기를 집는다.
- **드롭 대상 판정** → `dragover` 리스너 대신 `document.elementFromPoint(x, y)` 한 곳으로
  모으면 규칙("이건 소스이기만 하고 타겟은 아님", "요소 밖이면 컨테이너 끝")이
  한 함수 안에 모여 오히려 단순해진다.
- **화면 끝 자동 스크롤** → rAF 루프. ⚠ **스크롤할 때마다 히트테스트를 다시 돌려야**
  삽입선이 실제 위치를 따라간다(스크롤하면 커서 아래 요소가 바뀐다).
- **창 밖에서 버튼을 뗐을 때 정리** → `mouseup` 외에 `window` `blur`에도 정리를 건다.

**⚠ `preventDefault`는 `mousedown`에 건다, `pointerdown`이 아니라.**
`pointerdown`을 취소하면 호환 마우스 이벤트가 통째로 억제돼 **`dblclick`이 죽는다**
(제목 더블클릭 이름변경 같은 기능이 조용히 사라짐). `mousedown` 쪽 `preventDefault`는
텍스트 블록선택·포커스만 막고 `click`/`dblclick`은 그대로 발생한다(실측).

**⚠ CSS 특정도 함정**: 미리보기용 `.drag-preview { position: fixed }` 를 원본 클래스
`.widget { position: relative }` 보다 **앞**에 두면 특정도가 같아 뒤 규칙이 이겨 fixed가
안 먹는다. `.widget.drag-preview` 로 올리고 위치도 뒤로 옮길 것.

## 대가

- **원인을 끝내 모른다.** 왜 헤더에서 시작한 네이티브 드래그만 죽었는지는 미해결로
  남았고, 같은 코드베이스의 다른 네이티브 DnD(정렬 패널 행 재배치)는 손대지 않아
  거기서 재발하면 다시 만난다.
- **터치/펜 미지원** — 마우스 이벤트만 배선했다. 필요하면 pointer 이벤트로 올려야
  하는데, 그때 위 `preventDefault` 함정을 다시 만난다.
- 임계값(5px)으로 클릭과 드래그를 직접 갈라야 한다 — 네이티브는 이걸 알아서 해줬다.

## 일반화

**"격리 검증은 통과하는데 실사용에서만 실패"가 2번 이상 반복되면, 고쳐야 할 것은
구현이 아니라 「검증할 수 없는 메커니즘을 쓰고 있다는 사실」이다.**
브라우저·OS가 소유한 상태머신(네이티브 DnD, IME, 파일 다이얼로그, 네이티브 스크롤
관성)에 로직을 얹으면 그 안을 관측할 수단이 없어, 실패할 때마다 사용자 왕복이
필요해진다. 자기 이벤트 위에 다시 구현하면 코드는 늘지만 **관측 가능해진다** —
교체의 이득을 "더 잘 동작할 것"이 아니라 **"검증 루프가 닫힌다"** 로 계산할 것.
